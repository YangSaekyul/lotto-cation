# 2차 — Antigravity 기능 구현 브리프

**작업 경로:** `/Users/yang/CODE/lotto-cation`

## 전제

Codex가 만든 UI를 유지하고 **기능만 완성**한다. 디자인 시스템/레이아웃을 임의로 갈아엎지 말고, 실제 데이터와 연결해 모바일 웹을 동작하게 한다.

## 데이터 원천 (이미 최신화됨)

- `data/winning_store_records_current.json`: 79,592건, 최신 1234회까지
  - 262~1168회: 1·2등 legacy 이력
  - 1169~1234회: 동행복권 공식 1~5등 이력, 좌표 포함
- `data/official_draw_results_1169_1234.json`: 1169~1234회 공식 번호·등수별 당첨자 수
- 공식 최신 검증 기준: 1234회, 2026-07-25
- 새로고침 스크립트: `scripts/refresh_official_lotto_data.py`

## 구현 범위

1. 데이터 import/정규화
   - Postgres(Supabase 권장)에 stores, winning_store_records, draw_results, store_reports 테이블 생성
   - 동일 판매점은 `store_id` 우선, 없으면 정규화한 이름+주소로 병합
   - 온라인 판매점은 지도에서 제외

2. 지도/근처 검색
   - Naver Maps JavaScript API를 연결한다. 키는 `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID` 환경변수만 사용하고 커밋 금지.
   - 사용자 위치 허용 시 1/3/5/10km 반경의 판매점을 거리순으로 보여준다.
   - 위치 거부 시 주소 검색으로 중심을 정한다.
   - 1등/2등만 강하게 강조, 3등은 필터 시, 4·5등은 상세 이력에서 보여준다.
   - 1169회 이후 공식 좌표가 있는 지점부터 신뢰 표시하고, 구 데이터의 좌표 없는 지점은 지오코딩 작업 완료 전 지도에 표시하지 않는다.

3. 판매점 상세/길찾기
   - 주소, 거리, 1~5등 이력, 최근 당첨 회차, 데이터 기준시각 표시
   - 네이버 지도 길찾기 URL을 새 창으로 연다. 앱 미설치 시 웹 fallback을 검증한다.

4. 회차/통계
   - 최신 회차의 6개 번호, 보너스, 1~5등 당첨자 수 표시
   - 1/3/6/12/60개월 번호 빈도 API와 탭 구현
   - 통계는 ‘출현 횟수’만 표시하며 추천·확률 우위 표현 금지

5. 최다 이력/제보
   - 1·2등 기준 기본 정렬, 등수/지역 필터
   - 폐점/이전/주소오류/기타 제보 form + `pending` 저장
   - rate limit/honeypot, 개인정보 최소 수집

6. 데이터 갱신과 품질
   - 매주 공식 최신 회차 확인 → 결과/당첨 판매점 upsert → 데이터 기준시각 갱신 cron
   - API 실패 시 기존 데이터를 덮어쓰지 않고 알림/로그 남김
   - 소스 URL·수집시각 없이 결과를 공개하지 않는다.

## 제외 범위

- 로그인, 결제, 후원형 번호 추천, 광고는 구현하지 않는다.
- 후원형 번호 추천은 법률/PG 정책 검토와 무료 UX 검증 이전에는 시작하지 않는다.
- 과거 당첨을 다음 당첨 가능성으로 암시하지 않는다.

## 검증 기준

- 데이터 import idempotency 테스트
- 거리 계산/반경 필터/온라인 판매점 제외 테스트
- 최신 회차 JSON schema 테스트
- 위치 허용/거부, 길찾기 URL, 지도 API 로드 실패의 모바일 E2E 테스트
- 360/390/430/768px 실제 브라우저 확인
- `npm run lint`, `npm run test`, `npm run build` 통과
- 커밋 메시지는 한글
