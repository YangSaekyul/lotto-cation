# 1차 — Codex 디자인 구현 브리프

**작업 경로:** `/Users/yang/CODE/lotto-map`

## 역할과 제한

너는 **디자인 구현만** 담당한다. 기능, DB, API, 인증, 결제, 지도 API 연동, 실제 데이터 로딩은 구현하지 마라. 정적 목업 데이터만 사용하되, 후속 개발자가 실제 기능을 연결하기 쉽게 타입·컴포넌트 경계를 만든다.

## 제품

**로또케이션 (LottoCation)** — 30대 이상이 휴대폰에서 가까운 로또 판매점과 과거 당첨 이력을 쉽게 찾는 모바일 웹.

## 구현할 화면

1. `/` 지도 홈: 지도 영역 placeholder, 현재 위치 버튼, 1~5등 필터, 판매점 바텀시트
2. `/store/[id]`: 판매점 상세, 이력, 큰 `네이버 지도 길찾기` 버튼, 정보 제보 버튼
3. `/draw/latest`: 직전 회차 번호 6개+보너스, 1~5등 당첨자 수
4. `/stats`: 1개월/3개월/6개월/1년/5년 탭, 1~45 번호 빈도 그리드
5. `/stores/ranking`: 최다 당첨 이력 탭과 지역 필터
6. `/report`: 폐점/이전/주소 오류 제보 폼 목업

## 모바일 디자인 절대 조건

- 360~480px가 기준, 768px 태블릿까지 대응. PC 전용 대시보드 금지.
- 밝은 `#F7F8F5` 배경, 짙은 `#17211C` 글자, 행동색 `#0F8A5F` 하나만.
- 본문 16px 이상, 핵심 숫자 20~28px, 클릭 요소 최소 48px.
- 카드 16px radius와 얇은 테두리. 과한 그림자·그라데이션·다크모드 금지.
- 지도는 화면 상단 대부분을 차지하고, 판매점 목록은 드래그 가능한 바텀시트처럼 보여야 한다.
- 하단 고정 메뉴: 지도 / 최근 결과 / 번호 통계 / 최다 판매점.
- 1등 빨강, 2등 주황, 3등 파랑, 4·5등 중립색. 색만으로 의미를 전달하지 말고 텍스트 병기.

## 정직성 문구

- ‘명당’, ‘당첨 예측’, ‘확률 상승’, ‘AI 추천’ 문구 금지.
- 판매점 상세/통계에: `과거 당첨 이력과 번호 통계는 향후 당첨 확률을 높이지 않습니다.`
- `동행복권과 무관한 정보 서비스`를 푸터에 표시.

## 기술 요구

- Next.js App Router + TypeScript + Tailwind CSS.
- Lucide 아이콘만 사용. 이미지 생성·외부 유료 라이브러리 금지.
- `components/`, `lib/mock-data.ts`로 분리.
- `npm run lint`, `npm run build`가 통과해야 한다.
- 기능 구현용 API 호출, env, Naver API 키, 결제 SDK는 절대 넣지 않는다.
